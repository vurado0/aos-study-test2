Theorie · UD1

Memory Management

Vom executable zum Prozess, Fragmentation, Segmentation, Paging, Multilevel, Pentium, x86-64, Memory Safety.

1.1Vom Programm zum Prozess

Kette und Zeitpunkte

source → compiler → object module → linker (+ libraries) → executable → loader → Prozess

  • linking = vor der Ausführung.
  • loading = beim Prozessstart; dynamic libraries während der Laufzeit.
  • Erst zur Laufzeit entstehen: heap, memory-mapped files, shared zone, dynamic libs, stacks.
  • Program vs. process: gleicher Code, jeder Prozess hat eigene Datenkopie.
BegriffBedeutung
Address spacealle Adressen, die ein Prozess referenzieren kann
Virtual address spacepro Prozess unabhängig
Physical address spacegemeinsam für alle

Prozess nutzt nur virtual addresses → Übersetzung virtual → physical, transparent.

1.2Memory hierarchy, Locality, Fragmentation

Memory hierarchy

klein, schnell, teuer: registers, on-chip cache
groß, langsam, billig: main memory, disk, tape
Funktioniert wegen locality.

Spatial locality

Position referenziert → Nachbarn bald auch. Arrays, sequentieller Code.

a[3]a[4]a[5]a[6]

Temporal locality

Position bei t referenziert → bald wieder. Schleifen, Stack, Unterprogramme.

for(i…) sum += x; ← sum ständig

Knuth (1971)

< 4 % eines Programms verursachen > 50 % der Laufzeit.

Fragmentation

Internal fragmentation

Lücke innerhalb einer Partition (Partition − Objekt). Bei MFT und Paging (letzte Seite halb leer).

External fragmentation

Freier Speicher in unbrauchbare Lücken zwischen Partitionen zerstückelt. Bei MVT und Segmentation → evtl. compaction.

1.5Segmentation

Virtual address = segment number s + offset d. Tabelle = Segment Table (ST) mit base + limit (+ Rechte). Große ST im RAM, Register STBPR zeigt darauf → 2 Speicherzugriffe pro Referenz.

RechnerSegment-Übersetzung 16-bit Adresse: 2 Bit Segment | 14 Bit Offset
oder

Segment Table (editierbar)

Rechenweg

Physischer Speicher (64 KiB)

Segment bestimmen

(a) aus den high-order bits der Adresse (wie oben).
(b) aus einem segment-selector register (Pentium: CS, DS …), unabhängig von den Adressbits.

Bewertung

✓ keine internal fragmentation, Segmente wachsen, sharing (libc: gleiche base in beiden STs, read-only/execute).
✗ external fragmentation, compaction.

Physical = base + d (Addition!). Limit-Check vor der Addition: d ≥ limit → trap / segmentation fault. Segment ist ganz oder gar nicht im Speicher – das löst erst demand paging.

1.6Paging

Physischer Speicher in frames, virtueller in pages (gleich groß). Virtual address = page number p + offset d. Tabelle = Page Map Table (PMT), Register PTBPR.

RechnerPaging-Übersetzung Schritt für Schritt Klick auf eine PMT-Zeile setzt die Seite

Page Map Table

Rechenweg

Rezept

  1. offset bits = log₂(page size), Rest = page number
  2. PMT[p] → frame f (+ valid/present bit)
  3. PA = f · page size + d = f ‖ d (Konkatenation)

Bewertung

✓ keine external fragmentation; sharing einzelner pages (feiner als Segmente).
✗ internal fragmentation (Ø ½ Seite); PMT kostet selbst frames.

Größere pages → mehr internal frag., kleinere PMT.

1.7Multilevel paging & Format der virtual address

Wird die PMT zu groß, wird die PMT selbst gepaged: table | page | offset. Second-level tables existieren nur für genutzte Bereiche (sparse address space).

RechnerAdressformat herleiten jede Tabelle belegt genau 1 page
IA-32 mit 4 KiB pages: einstufige PMT = 2²⁰ · 4 B = 4 MiB pro Prozess, auch wenn er nur 12 KiB nutzt. Zweistufig: 4 KiB Directory + 1 bis 3 · 4 KiB = 8–16 KiB.

Paged segmentation vs. segmented paging

Paged segmentation = segments made of pages: Segmenteintrag zeigt auf eine page table. Pionier Multics, genutzt vom Pentium. Segmented paging wird in der Praxis nicht verwendet. Nachteil: komplexere Hardware.

1.8TLB – Translation Lookaside Buffer

  • Ohne TLB: 2 Zugriffe (PMT + Daten), bei n Ebenen n+1.
  • TLB = kleiner Cache für page-table entries; dank locality meist hits.
  • Skylake: L1 DTLB 64, L1 ITLB 128, L2 ~1536 entries.
  • Eviction macht die Hardware (page-table walker). OS invalidiert nur: context switch, INVLPG.
  • Ausnahme: software-managed TLB (MIPS) → miss = trap ans OS.

1.9Fallstudie Pentium (IA-32)

Logical address = selector (16 bit) : offset (32 bit) → segmentation stage → linear address (32 bit) → paging stage (10 | 10 | 12) → physical address.

RechnerSelector → Descriptor → linear → physisch

Descriptor-Tabellen (Beispiel)

Rechenweg

Selector (16 bit)

13 bit index · 1 bit TI (0 = GDT, 1 = LDT) · 2 bit RPL (Ring 0–3). Register: CS, DS, ES, SS, FS, GS.

Descriptor (8 Byte)

base 32 bit · limit 20 bit · attributes 12 bit. GDT/LDT je bis 2¹³ = 8192 Einträge. G-Bit: G=0 limit in Byte (max 1 MiB), G=1 in 4-KiB-pages (max 4 GiB).

Segment kommt aus CS, nicht aus den PC-Bits → PC ist reiner offset. Linear address ≠ physical address.

1.10x86-64: canonical addresses & four-level paging

PrüferCanonical? + Indizes PML4 / PDPT / PD / PT

Regeln

Nur untere 48 bit genutzt. Bits 48–63 = Kopie von Bit 47 (sign-extension), sonst fault. PML4 → PDPT → PD → PT, 4 Zugriffe statt 2. PS-Bit: 2 MiB (PD) / 1 GiB (PDPT) huge pages.

Segmentation fast weg

Long mode: Segmente flat (base 0). Nur FS/GS arbeiten noch: thread-local storage. Paging macht praktisch alles.

1.11Memory Safety & ASLR

VisualisierungStack buffer overflow char buf[16]; strcpy(buf, input);

Format string

printf(buffer);        // ✗ verwundbar
printf("%s", buffer);  // ✓ sicher

%x / %p → arbitrary read vom Stack · %n → arbitrary write. Arbeitet relativ zum laufenden Stack.

ASLR

Randomisiert stack, heap, mmap/libs, executable (nur mit PIE). ASLR = dynamic relocation für Sicherheit. x86-64: innerhalb des canonical space.

AngriffBraucht feste Adresse?ASLR hilft?
Buffer overflowJa (Ziel für return address)✓ mitigiert
Format stringNein (relativ zum Stack)✗ nein

ASLR mitigiert eine Angriffsklasse, eliminiert aber keine memory-safety bugs.

Virtual Memory

Page Faults, Thrashing, Working Set, Policies, Replacement-Algorithmen, Fallstudien.

2.1Was ist Virtual Memory?

Definition

Prozesse laufen, ohne vollständig im MM zu sein, und dürfen größer als der MM sein. Entkoppelt virtual/physical address space, Disk = Erweiterung des MM. Basis: locality. Gesteuert vom OS mit Hardware-Support.

Advantages

  1. Transparente Transfers Disk ⇔ MM
  2. Max. Prozessgröße = virtual address space + Disk
  3. Höherer degree of multiprogramming
  4. Weniger I/O (nur Benötigtes)

Hardware requirements

  • MMU (page map table management unit)
  • Bits: presence · modification (dirty) · reference
  • Auxiliary storage (swap / Datei)
  • Unterbrechbare Instruktionen: Neustart nach PF

2.6Replacement-Algorithmen

Optimal (OPT)

Seite raus, die am längsten nicht mehr gebraucht wird. ✓ niedrigste Rate, Benchmark. ✗ nicht implementierbar.

FIFO

Seite raus, die am längsten im MM ist. ✓ einfach. ✗ schlecht, Belady's anomaly.

LRU

Seite raus, die am längsten nicht benutzt wurde. ✗ teuer (Zeitstempel bei jedem Zugriff). Stack algorithm → kein Belady.

Kriterien: low overhead, kein Tuning, gute LRU-Approximation. Reference string: aufeinanderfolgende Zugriffe auf dieselbe Seite = eine Referenz.

SimulatorReference string Schritt für Schritt

PFs in Abhängigkeit der Frame-Anzahl (gleicher String)

Folien-String mit FIFO: 3 frames → 9 PFs, 4 frames → 10 PFs = Belady's anomaly. OPT 7/6, LRU 10/8. FIFO = älteste geladene Seite, LRU = am längsten nicht benutzte.

2.7LRU-Approximationen

Global clock (4.3 BSD)

Circular list + R-Bit. Laden: R←0. Referenz: R←1. Periodisch setzt ein rotierender Zeiger R←0. PF: R=0 → ersetzen, R=1 → R←0, weiter.

FIFO 2nd chance

FIFO-Queue: R=1 → R←0, ans Ende; R=0 → ersetzen. ✓ wenig overhead. ✗ alle R=1 → degeneriert zu FIFO.

Unterschied zum clock: R-Bits nur beim PF-Durchlauf gelöscht, nicht periodisch.

NFU + aging

Timer-Interrupt: R=1 → counter++, dann alle R←0. PF: kleinster counter raus. Problem: alte Vielnutzer bleiben. Aging: counter >> 1, R ins MSB.

SimulatorNFU vs. Aging (8-bit counter)

R-Bits der Seiten setzen, dann Clock-Tick. Oder das Tanenbaum-Beispiel abspielen.

SimulatorLinux page aging (kswapd)

Start age = 3 · Zugriff +3, max 20 · kswapd-Lauf: unbenutzt −1 · Opfer = niedrigstes age.

Warum zeigt listfree auf das letzte Element?

Zeiger auf das letzte gibt O(1) Zugriff auf das erste (frt[last].next) und O(1) Anhängen am Ende. Leer = -1.

Ersten freien Frame nehmen

vorher (listfree = F3)

firstF0→F1→F2→last = listfreeF3↩ F0
last  = S->listfree;          // F3
frame = S->frt[last].next;    // F0 = erstes
if (frame == last) S->listfree = -1;    // war einziges
else S->frt[last].next = S->frt[frame].next; // F3 → F1

nachher

firstF1→F2→last = listfreeF3↩ F1

FIFO: Frame in listoccupied einfügen

vorher (listoccupied = F1), neu: F5

firstF4→lastF1↩ F4
S->frt[F5].next = S->frt[S->listoccupied].next; // F5 → F4
S->frt[S->listoccupied].next = F5;              // F1 → F5
S->listoccupied = F5;                           // F5 = letztes

nachher

firstF4→F1→lastF5↩ F4

Opfer wählen = erstes nehmen und listoccupied = victim setzen: der Ring dreht sich, das Opfer ist jetzt „letztes“ und bekommt die neue Seite.

L8Typische Testfragen zum Lab

Was macht die Hardware, was das OS?

HW (MMU): Adressübersetzung, Gültigkeitsprüfung, Present-Check, Modified/Referenced/Timestamp setzen, Page-Fault-Trap. OS: Fault behandeln, freie Frames (Frame-Tabelle), Opfer wählen, Seite laden, dirty Seite zurückschreiben.

Wozu das modified-Bit?

Nur dirty Seiten müssen beim Ersetzen auf Disk geschrieben werden („page dumps“).

Wozu die Frame-Tabelle?

Freie Frames schnell finden und Frame → Seite zuordnen, ohne die ganze Seitentabelle zu durchsuchen.

Warum zirkuläre Liste mit Zeiger aufs letzte Element?

O(1) Zugriff aufs erste (last.next) und O(1) Anhängen am Ende.

Rückgabe bei illegaler Adresse?

~0U (alle Bits 1), numillegalrefs++.

Probleme von LRU?

Uhr-Überlauf, teure Suche O(frames), Hardware-Aufwand pro Zugriff → Approximation durch 2nd chance.

Warum terminiert die 2nd-chance-Schleife immer?

Jeder Durchlauf löscht R-Bits. Spätestens nach einer Runde sind alle 0 → verhält sich wie FIFO.

Warum ist Optimal nicht realisierbar und trotzdem im Lab?

Braucht die Zukunft. Simulator lädt die ganze Trace vorab („cheating“) und liefert die ideale Untergrenze zum Vergleich.

Warum T8 bei MER mit 4 Elementen?

Mergesort braucht ein Zusatzarray gleicher Größe.

Was erwartet der Random-Test 1 3 HEA DES 4 D?

20 Reads, 17 Writes, 7 Page Faults, 2 Page dumps (laut Lab-Anleitung, mit dem Original-gen_trace).

Top-Fallen vor der Prüfung

  1. Internal ↔ external: paging = internal, segmentation/MVT = external.
  2. Segmentation: limit-Check vor der Addition; base + d. Paging: f ‖ d.
  3. Pentium: selector 16 bit (13 + 1 + 2), offset 32 bit; linear ≠ physical.
  4. x86-64: 48 bit genutzt, Bits 48–63 = Bit 47.
  5. Belady nur bei FIFO, nicht bei OPT/LRU (stack algorithms).
  6. Reference string: direkte Wiederholungen zählen einmal.
  7. Global → thrashing-Risiko (Unix/Linux); local → overhead (VMS/Windows).
  8. ASLR hilft gegen buffer overflow, nicht gegen format string.
  9. Placement ist bei paging irrelevant.
  10. TLB eviction macht auf x86 die Hardware; OS invalidiert nur.
  11. Lab: listfree zeigt aufs letzte, erstes = frt[last].next; leer = -1.
  12. Lab: MMU = sim_mmu + reference_page; alles andere OS.
